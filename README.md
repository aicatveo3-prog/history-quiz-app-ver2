# 한국사 기출 학습

폴더의 `모의고사 열기.html`을 더블클릭하여 실행합니다. 이미 열어 둔 사이트는
새로고침(F5)하면 새 학습 화면으로 바뀝니다. 설치나 인터넷 연결 없이 사용합니다.
`site/dist` 폴더가 함께 있어야 합니다.

## 학습 순서

1. 제74회·제78회·제79회 심화 중 회차를 선택합니다.
2. 한 문제의 원본 사료·사진·보기를 읽고 답 번호를 고릅니다.
3. **정답 확인**을 누르면 정오답, 정답 번호, 핵심 단서와 해설이 표시되고, 문제 아래에 **자세한 해설**(자료 읽는 법, 보기별 분석, 배경 이론, 암기 포인트)이 펼쳐집니다.
4. 해설을 읽고 **다음 문제**를 눌러 넘어갑니다.
5. 50문항을 마치면 원본 배점에 따른 점수와 오답을 확인합니다. **해설 보기**로 복습합니다.

상단의 **문제 이동** 바를 끌어 원하는 문항으로 바로 이동합니다. **문항 번호로 이동**을
펼치면 1~50번을 직접 누를 수 있으며, 현재 문제·정답·오답·확인 전 상태가 구분됩니다.
이동해도 선택한 답과 해설 확인 기록은 유지됩니다. 50번을 먼저 푼 경우에는
**아직 안 푼 문제로** 버튼으로 미학습 문항에 돌아갈 수 있습니다.

시간 제한은 없습니다. 확인한 답은 수정할 수 없으며, 이전 문제에서 해설을 다시
읽을 수 있습니다. 처음부터 다시 풀면 해당 회차의 학습 기록이 새 풀이로 바뀝니다.
원본 PDF 열기도 지원합니다. 번호 선택은 키보드 방향키로도 가능합니다.
정답을 확인한 뒤에는 문제 카드의 `문제 보기` 스위치를 꺼서 문제를 접고 해설만 볼 수 있습니다(다시 켜면 펼쳐집니다).

## 단원별 풀기 · 특수 분류

메인 화면 위쪽 탭으로 풀이 방식을 고릅니다.

- **회차별 풀기**: 기존 방식(회차 50문항).
- **단원별 풀기**: 시대 9개, 주제 78개. 시대 전체 또는 주제 하나를 골라 여러 회차의 문항을 이어서 풀 수 있습니다(550문항 전부 정확히 한 주제에 들어 있음).
- **특수 분류**: 유물·문화유산(31), 지역사(18), 시대 비교·통사(10). 이 문항들은 시대 단원에도 그대로 들어 있습니다(양쪽에 보임).

묶음의 진도는 묶음마다 따로 저장되어 회차별 기록과 섞이지 않습니다(`korean-history-study-v2-<묶음 id>`).
묶음 안에서는 `제72회 47번`처럼 원래 회차와 번호가 표시되고, 지역사 문항에는 지역 태그가 붙습니다.
해설은 해설이 있는 회차(74·78·79회) 문항에서만 나옵니다.

분류 원고는 `content/unit-map.json`입니다(시대 → 주제 → 문항 `"회차-번호"`, 특수 분류는 `special`).
고친 뒤 `python tools/build_units.py`를 실행하면 `dist/units.js`가 만들어집니다. 550문항 누락·중복, 존재하지 않는 문항은 빌드에서 검사합니다.
주제 id는 시대 id와 목록 순서(`goryeo-3`)로 만들어지므로, 주제 순서를 바꾸면 id와 저장된 묶음 진도가 달라집니다.

## 화면 디자인

기존 초록색 디자인을 바탕으로 제목, 여백, 카드, 답안 버튼과 해설을 다듬었습니다.
문제 이동 영역은 간결하게 줄이고, 해설의 핵심 단서를 따로 강조했습니다.
넓은 화면에서는 문제와 해설을 나란히, 작은 화면에서는 세로로 배치합니다.
시안 전환 메뉴는 풀이 화면에서 제거했습니다. 이전에 선택했던 시안과 관계없이
개선된 기존 디자인으로 열리며, 학습 기록은 유지됩니다.
이전 시안 이미지는 `dist/designs.html`에 참고용으로 보관했습니다.

## 넓은 화면의 풀이 배치

900px보다 넓은 화면에서는 왼쪽에 **문제와 선택지(①~⑤), 정답 확인/다음 문제 버튼**을 고정하고(스크롤해도 따라옴),
오른쪽 넓은 칸에는 **정답 결과와 해설만** 보여 줍니다. 해설을 읽는 동안 문제와 보기가 계속 보입니다.
본문 폭은 최대 1840px까지 넓어지고, 문제 칸 너비는 문제 이미지의 가로세로 비율과 화면 높이로 계산해
나머지 폭을 모두 해설 칸이 씁니다. 해설 칸이 900px 이상이면 자세한 해설을 좌우 두 묶음
(자료 읽는 법·보기별 분석 / 배경 이론·암기 포인트)으로 나란히 보여 줍니다.
가능하면 문제 전체가 한 화면에 들어오며, 화면이 낮으면 문제 칸 안에서만 스크롤됩니다(선택지 줄은 항상 보임).
정답을 확인하면 위치를 자동으로 맞추고, 해설 맨 아래에도 `다음 문제` 버튼이 있습니다.
좁은 화면(모바일)은 문제 → 선택지 → 정답/해설 순서로 세로 배치합니다. 스타일은 `dist/split.css`입니다.

### 문제 접기

정답을 확인하면 문제 카드 제목 줄에 `문제 보기` 스위치(켜짐=초록/오른쪽, 꺼짐=회색/왼쪽)가 나타납니다. 끄면 문제 이미지와 선택지가 접히고, 문제 칸은
제목·스위치·`다음 문제` 버튼만 남은 좁은 카드가 되어 나머지 폭을 모두 해설이 씁니다. 다른 문제로 넘어가면 다시 펼쳐진 상태로 시작합니다.
(답을 고르기 전에는 접을 수 없습니다. 예전의 `문제 크게 보기` 창은 없앴습니다.)

### 화면 배분 도구

문제와 해설 사이의 **막대를 끌어서** 문제 칸과 해설 칸의 너비 비율을 직접 바꿀 수 있습니다(넓은 화면 전용, 별도 버튼 없음).

- 막대를 더블클릭하면 자동 맞춤(화면 높이에 맞춰 자동 계산)으로 돌아갑니다.
- 키보드: 막대에 포커스를 두고 ←/→(Shift는 크게), Home/End(최소/최대), Enter(자동 맞춤)
- 정한 비율은 이 브라우저에 저장되어 다음 문제와 다음 방문에도 유지됩니다. 비율은 화면 너비에 대한 %로 저장하므로
  창 크기가 바뀌어도 해설 칸 400px·문제 칸 340px 아래로는 줄어들지 않게 자동 보정됩니다.
- 문제 칸을 넓히면 문제 이미지가 커져서 화면보다 길어질 수 있으며, 이때는 문제 칸 안에서 스크롤됩니다(선택지 줄은 항상 보임).

## 자료와 해설

원본 문제 PDF에서 150문항을 개별 이미지로 잘라 사진·사료·선택지를 보존했습니다.
정답과 배점은 제공된 원본 정답표에서 추출했습니다. 원본 `한능검 기출` 폴더는
수정하지 않았습니다.

원본에는 해설이 없어 **150문항의 학습용 해설을 별도 작성**했습니다. 공식 해설이
아니며, 각 문항의 단서·정답인 이유·헷갈리는 보기와의 차이를 설명합니다.
일부 세부 사항은 국사편찬위원회 우리역사넷과 한국학중앙연구원 자료를 확인했고,
해당 문항에 참고 링크를 넣었습니다. 핵심 학습 기능은 오프라인에서도 동작합니다.

## 회차 추가 (문제·정답만)

제70~73회, 제75~77회, 제80회 심화는 **문제와 정답만** 들어 있고 해설은 아직 없습니다(홈에는 `정답 · 해설 준비 중`으로 표시되고,
정답을 확인하면 `해설 준비 중` 안내가 나옵니다). 이론 정리 페이지는 해설이 있는 74·78·79회 150문항만 다룹니다.

새 회차 PDF(`한능검 기출/…n회 심화 문제.pdf`, `…정답.pdf`)를 폴더에 넣은 뒤 아래처럼 추가합니다.

```
python tools/add_exams.py 81 82
```

- 문제 PDF는 스캔 이미지라서 Tesseract(OCR, kor+eng)로 문항 번호 위치를 찾아 문항별 이미지로 자릅니다.
  1~50번이 순서대로 정확히 한 번씩 찾아져야 하며, 그렇지 않으면 멈추고 알려 줍니다.
- 정답표는 텍스트에서 읽습니다(동그라미 숫자 형식과 일반 숫자 형식 모두 지원, 50문항·100점 검증).
- 필요한 도구: Python의 `pdfplumber`, `pypdfium2`, `Pillow`, 그리고 `C:/Program Files/Tesseract-OCR`.
- 기존 회차(`dist/exams.js`의 다른 항목)는 건드리지 않고 새 회차만 덧붙입니다.
- 나중에 해설을 붙일 때는 `content/<회차>.tsv`와 `content/detail-<회차>a/b.json`을 만들고
  `build_explanations.py` → `build_details.py`를 실행합니다. (이론 정리는 별도 원고를 쓰므로 영향을 받지 않습니다.)

## 자세한 해설

기출 풀이 화면의 해설은 새로 만드는 중입니다. 현재는 **제77회 50문항**에만 해설이 있고,
나머지 회차는 정답만 확인할 수 있습니다(`해설 준비 중`). 정답을 확인하면 문제 옆에 아래 4단 해설이 표시됩니다.

1. **자료 읽는 법**: 지문의 어떤 단서로 시대·인물·사건을 확정하는지
2. **보기별 분석**: ①~⑤ 각각이 왜 정답이거나 오답인지 (내가 고른 답은 따로 표시)
3. **배경 이론**: 해당 주제의 연표와 개념 정리
4. **암기 포인트**: 헷갈리는 쌍을 구분하는 한 줄 요약

원고는 `content/<회차>.tsv`(간단 해설)와 `content/detail-<회차>a/b.json`(a는 1~25번, b는 26~50번)입니다.
고친 뒤 `python tools/build_explanations.py`, `python tools/build_details.py`를 실행하면
`dist/explanations.js`, `dist/details.js`가 만들어집니다. 빌드는 정답 일치와 보기 개수(5개)를 검사하며,
50문항 중 일부만 있는 회차도 허용합니다(해설이 없는 문항은 `해설 준비 중`으로 표시).
`자료 읽는 법`·`배경 이론`·`암기 포인트`에 줄바꿈(`\n`)을 넣으면 화면에서 단락이 나뉩니다.
공식 해설이 아니라 학습용으로 새로 작성한 내용입니다.

## 이론 정리

상단 메뉴의 **이론 정리**(`dist/theory.html`)에서 150문항의 해설을 9개 시대, 85개 주제로 묶어 볼 수 있습니다.
주제 한 줄에 출제 횟수와 문항(예: `74-11` = 제74회 11번), 암기 포인트가 표로 나오고,
누르면 배경 이론·헷갈리는 구별·출제 문항이 펼쳐집니다. 시대 선택, 키워드 검색,
'2회 이상 출제만' 필터, 모두 펼치기/접기를 지원하고 인쇄하면 전부 펼쳐집니다.

- **북마크**(`dist/bookmarks.js`, `bookmarks.css`): 기출 풀이·단원별 풀이·이론 정리의 문제 창이 같은 북마크를 씁니다. 틀린 문제는 자동으로 들어오고(풀이 기록이 바뀔 때마다 맞춰 봄), 문제 화면의 `☆ 북마크` 버튼으로 직접 담거나 뺄 수 있습니다. 자동으로 들어온 문제는 다시 맞히면 빠지고, 직접 담은 문제는 맞혀도 남으며, 직접 뺀 문제도 다시 틀리면 돌아옵니다. 모아 보기는 기출 풀기 첫 화면의 `북마크` 탭(`#bookmarks`)이고, 이론 정리에서는 번호 칩에 ★가 붙고 `★ 북마크만`으로 주제를 거릅니다. 기록은 `korean-history-study-v2-bookmarks`(계정에는 `progress/bookmarks`)에 문제별로 저장되며 로그인하면 풀이 기록처럼 문제마다 더 최근 쪽으로 합쳐집니다. 검사: `node tools/bookmarks-test.mjs`.
- **문제 표시**(`dist/theory-marks.js`): 문제는 풀었든 안 풀었든 모두 보이고, 푼 문제의 번호만 진한 테두리로 구분합니다. 맞혔는지 틀렸는지는 구분하지 않습니다. 주제 줄의 출제 횟수 칸에 이 주제에 나오는 문제 수와 번호 링크 전체, 소제목 옆에 `출제 N · 푼 문제 M` 묶음(누르면 번호 칩 N개, 칩을 누르면 해당 구절로 이동), 본문 구절에 형광펜(칠함 = 정답 근거, 밑줄 = 오답 보기, `×N` = 출제 횟수)이 나옵니다. `형광펜 끄기`로 끌 수 있습니다.
- **문제-구절 연결**(`dist/theory-tags.js`): 한 문제를 여러 시대·주제에 연결할 수 있고, 문제마다 정답 근거와 오답 보기 4개를 빠짐없이 연결합니다. 이론 글에 없는 보기는 구절 없이(`null`) 연결해 소제목 묶음에만 나타납니다. 구절을 누르면 문제마다 시험지 선다지 문장을 그대로 보여 줍니다(자료 단서로 걸린 문제는 정답 선다지, 순서 배열 문제만 자료 문장). 선다지 문장은 `dist/question-choices.js`(`node tools/build_question_choices.mjs`로 `content/questions-text/all.jsonl`에서 생성)에 있고, 연결 근거인 자료 문장은 `theory-tags.js`에 적으며 검사 도구가 시험지 자료와 대조합니다. 지금은 선사·고조선·초기 국가 23문제만 연결되어 있습니다. 고친 뒤 `node tools/check-theory-tags.mjs --era <시대 id>`로 빠진 보기, 없는 구절, 겹치는 구절을 검사합니다. 소제목 앞의 문단 번호가 바뀌면 연결도 함께 고쳐야 합니다.
- 문항 번호(`74-11`)를 누르면 이론 정리 화면 위에 **작은 문제 창**이 열립니다(`dist/theory-quiz.js`).
  문제 이미지를 보고 선택지 번호를 누르면 **바로 채점**되며 해설과 보기별 분석이 항상 펼쳐져 나타납니다.
  `다시 풀기`와 같은 주제의 다른 기출로 바꾸기도 가능합니다(방향키는 선택하지 않고 포커스만 옮깁니다). `닫기`, `이론으로 돌아가기`, `Esc`, 창 바깥 클릭으로
  돌아오며, `기출 페이지로 이동`을 누르면 해당 문항의 전체 풀이 화면으로 갑니다.
  Ctrl/Cmd/Shift+클릭이나 가운데 버튼 클릭은 작은 창 없이 바로 기출 페이지로 이동합니다.
  작은 창에서 고른 답은 문제별 풀이 기록에 남고 기출 풀이의 진도 기록에는 영향을 주지 않습니다. 이미 푼 문제를 열면 마지막 답과 해설이 보이고, `다시 풀기`로 다시 풀 수 있습니다.
  창 위쪽의 `이전 문제`, `다음 문제`는 창을 연 목록(구절의 문제 목록, 출제 문항, 소제목 칩)의 순서를 따르고, 목록이 없으면 같은 주제의 문제를 따릅니다.
- 문제 풀이 화면에서 정답을 확인하면 해설 칸의 버튼으로 해당 주제의 이론 정리로 이동합니다(해설이 없는 문항도 이동 버튼은 나옵니다).
- 주제 묶음은 `content/theory-map.json`에서 고칩니다(150문항이 정확히 한 번씩 들어가야 합니다).
- 고친 뒤 `python tools/build_theory.py`를 실행하면 `dist/theory-data.js`가 만들어집니다.
  문항 누락·중복은 빌드에서 검사합니다.
- 기본 내용은 74·78·79회의 원래 해설에서 가져온 것이며, 그 원고는 **이론 정리 전용**으로
  `content/theory-source/`(`74/78/79.tsv`, `detail-74·78·79a/b.json`)에 따로 보관합니다.
  기출 풀이 화면의 해설(`content/<회차>.tsv`)을 새로 쓰거나 지워도 이론 정리는 바뀌지 않습니다.
- `build_theory.py`는 `dist/theory-data.js`와 함께 문제 창용 해설 `dist/theory-explanations.js`
  (`window.THEORY_EXPLANATIONS`, `THEORY_DETAILS`)도 만듭니다. 이론 정리의 작은 문제 창은 이 파일만 사용합니다.
- **보강**(노란색 블록)은 기출 해설에 없는 추가 내용입니다. 한국민족문화대백과사전 등으로 확인한 출처 링크가 붙어 있고(점선 링크는 위키백과 보조 출처), `보강 내용 보기`로 숨길 수 있습니다.
  보강은 `content/theory-extra.json`에서 따로 관리하며, 항목마다 주제 id(`theme`), 유형(짝꿍·흐름·비교), 내용, 출처가 필요합니다. 이 파일을 고치고 `python tools/build_theory.py`를 실행하면 반영됩니다.
- 보강 후보 전체 목록(채택하지 않은 항목 포함)은 작업 폴더의 `tmp/theory-candidates.md`에 남겨 두었습니다.

## 한국사 연표

상단 메뉴의 **한국사 연표**(`dist/kings.html`)에서 선사 시대부터 현대까지를 하나의 연도 눈금 위에 이어서 볼 수 있습니다. 맨 앞 "선사·고조선" 구간(이론 정리 '선사·고조선·초기 국가')은 **표**(`tables`)로 정리했습니다. 선사 시대 구분 표(구석기·신석기·청동기·초기 철기: 도구·토기, 생활, 사회·신앙, 유적)는 연표 맨 위에, 초기 국가 비교 표(부여·고구려·옥저·동예·삼한: 위치·정치, 제천 행사, 혼인·장례, 법·경제·특산물)는 고조선이 멸망하는 기원전 108년부터 신라 건국(기원전 57) 사이에 놓이고, 모두 4줄에 걸칩니다. 고조선(단군 조선·위만 조선)도 표(성립, 정치·사회, 경제·문화, 대외 관계·멸망)로 기원전 2333~108년 칸에 놓습니다. 표는 `from`~`to` 연도 구간을 차지하고 표 높이만큼 그 구간의 눈금이 늘어나며(`measureNeeds`), 그 안에는 눈금을 그리지 않습니다. 600px 이하 화면에서는 행마다 카드로 쌓입니다. 표 항목은 `'키워드|설명|풀이 문장|혼동 주의: …|순서: …'` 형식이고, 상세 줄(풀이 한 문장, 혼동 주의, 순서)은 상단 막대 오른쪽 끝의 **자세히** 버튼을 켜거나 눈금을 150% 이상 확대하면 보입니다(좁은 화면은 버튼만, 선택은 브라우저에 저장). 표의 행마다 맨 위에 '핵심' 칩 한 줄(`formula`, 이론정리의 핵심 공식)이 있고, 열마다 색과 아이콘(`color`·`icon`)을 달아 항목 앞 점·열 머리·배경 색으로 구분합니다. 연표 박스(업적·사건)에도 같은 상세를 `x: '풀이|혼동 주의: …|순서: …'` 필드로 달 수 있고, 자세히를 켜면 박스 안에 펼쳐집니다(폭 1000px 미만은 줄 폭이 80~220px라서, 936년 이후의 띠를 옆 빈 줄까지 넓혀서(`is-xwide`) 보여 줍니다. 신라·후백제·발해와 줄을 같이 쓰는 태조 띠는 넓히지 않아, 폭이 좁은 화면에서는 태조의 상세가 보이지 않습니다). 지금은 고려의 사건 32개·업적 96개에 달아 두었습니다(고려 이후 시대는 아직 없음). 폭 1000px 이상에서는 자세히를 켜면 그 나라 띠를 옆 빈 줄까지 넓혀 박스를 분야별 3열(정치·제도·경제 / 사상·문화 / 대외·전쟁)과 연도 행(같은 연도는 같은 행, 연도 없는 일은 맨 위 "재위 중 정책" 묶음, 행 왼쪽에 연도 칩)으로 놓습니다(열은 박스의 `c`, 없으면 이론정리 주제 `th`·사건 종류로 정함). 상세 줄에는 `관련: …` 줄도 쓸 수 있습니다. 상세 글은 이론정리(선사·고조선·초기 국가) 문장을 합니다체로 옮긴 것이며, 선사 시대 구분·고조선·초기 국가 비교 세 표 모두에 있습니다. 구석기가 약 70만 년이라 눈금(`chart.scales`)을 크게 줄여 그리고, 기원전 4000년 이전 구간의 눈금 숫자는 구간마다 간격을 달리합니다(`ticksHtml`). 삼국~대한제국은 왕, 1910년부터는 같은 줄에 일제의 통치 방식 → 미군정 → 대한민국 정부(대통령)가 이어집니다.

- 연표는 한 장으로 이어지고, 줄은 처음부터 끝까지 폭이 같습니다(넓은 화면·좁은 화면 모두 4줄. 대한민국 임시 정부는 넓은 화면의 3번째 줄에만 보임). 화면 위에 붙어 있는 줄 이름표는 보고 있는 연도에 맞춰 바뀝니다.
  - 668년 이전: 고구려 · 백제 · 신라 · 금관가야 · 대가야 / 668년 이후: 발해 · 태봉→고려 · 신라 · 후백제
  - 943년부터: 시기 구분 · 고려→조선→일제 통치→미군정→정부(주요 사건은 띠 안 칸). 넓은 화면에서는 943년부터 시기 구분 줄이 이름표 폭(`--pw`, 150px)만 쓰고, 왕·정부 띠(`kt-pshift`)와 줄 이름표가 그만큼 왼쪽으로 넓어집니다. 1919~1945년은 넓은 화면의 일제 통치 줄 오른쪽(3번째 줄)에 대한민국 임시 정부(상하이·이동·충칭 시기)가 있습니다.
  - **자세히 보기 범위**: 연표의 모든 박스(왕의 업적·키워드·사건 556개)와 표 3개에 이론 정리 기준 상세 설명(`x`)이 들어 있습니다. 근거가 이론 정리에 없던 일부는 한국민족문화대백과·우리역사넷 등을 검색해 채웠습니다.
  - 상세를 보이는 방식: 고려·조선·현대 정부 띠는 PC에서 옆 빈 줄까지 넓혀 분야별 3열·연도 행으로 놓습니다. 옆 줄이 비지 않은 삼국·가야·남북국 줄과, 3번째 줄을 임시 정부가 쓰는 일제 강점기는 넓히지 않고 자기 줄 안에서 박스를 아래로 늘립니다(`SINGLE_LANE`, 601~999px에서는 `is-xshow`). 600px 이하 폰에서는 삼국·남북국 줄 폭이 80px뿐이라 상세가 보이지 않습니다.
- **눈금**은 뒤 시기일수록 넓습니다(1년당 943년 전 4px, 고려 8px, 조선 14px, 1800년 20px, 1863년부터 44px, 1876~1910년 64px). `Ctrl + 마우스 휠`(또는 `Ctrl + =/−/0`)로 25~400% 사이에서 자유롭게 늘이고 줄이며, 값은 이 브라우저에 저장됩니다.
- **띠 최소 높이**: 모든 띠에 이름이 들어가도록 24px 밑으로 줄지 않습니다. 업적 칸이 있는 띠는 칸이 모두 들어가는 높이 밑으로 줄지 않습니다. 모자란 만큼 그 구간의 눈금 간격이 넓어지고, 연도 숫자는 정확합니다.
- **시기 구분**(고려 이후): 무신 집권기·사화기·일제 강점기·제1~제6공화국 등을 1번째 줄 이름표와 같은 색 테두리로 묶고, 그 시기 띠를 시기 색으로 칠합니다(`periods`).
- **주요 사건**(고려 이후): 그 해에 재위한 왕·정부 띠 안에 업적 칸과 같은 모양의 박스로 넣고, 업적 박스 사이에 연도 순으로 끼웁니다. 박스 왼쪽 선과 연도 글자의 색이 분야이고, 종류는 침략·전쟁, 조약·외교, 정변·개혁, 봉기·운동, 경제·사회 5가지입니다(`events`). 왕이 바뀐 해의 사건은 새 왕 띠에, 복위로 재위가 겹치면 나중에 즉위한 쪽에 들어가고, 재위 단계(고종 등)가 있는 띠는 단계마다 나눠 넣습니다. 이름이 길면 박스 안에서 줄바꿈하고, 줄임 이름(`short`)이 있으면 600px 이하 화면에서 그것을 씁니다.
- **사건 최소 높이**: 사건 박스도 업적 칸이므로 띠 안 내용물 높이(`measureNeeds`)가 그 띠의 최소 높이가 되고, 모자라면 그 구간의 눈금 간격을 넓힙니다. 사건이 몰린 왕(고종 48개 등)의 띠는 그만큼 길어집니다.
- **띠 옆 왕의 일**(지금은 쓰는 나라 없음): 나라에 `wide`가 없고 `acts`가 있으면 화면 폭 1140px 이상에서 띠를 줄 폭의 37%로 좁히고 띠 바로 옆에 왕이 한 일을 그 해 높이에 적는 기능이 남아 있습니다. 신라·고려·조선은 `wide: 1`로 꺼 두어 모든 나라가 띠 안에 업적 칸을 적습니다.
- **업적 칸**: 삼국·발해·고려·조선 왕, 통치 방식, 정부, 임시 정부 띠 안의 작은 칸입니다(`keys`, 가야·후삼국 왕은 아직). `acts`로 옮긴 나라는 좁은 화면에서만 칸으로 보입니다. 앞쪽일수록 기출 해설에 많이 나온 것이며, 사건 줄·시기 설명과 겹치는 것은 넣지 않았고, 두 왕에 걸친 일은 양쪽에 모두 적습니다. 폰에서는 앞의 두 칸만 보입니다. 재위 중간에 시기가 바뀌는 띠는 그 해 전까지의 윗부분에 칸이 다 들어가도록 높이를 잡습니다.
- **재위 단계**: 재위가 긴 왕(지금은 고종)은 띠 안을 단계로 나눕니다(`stages`: 대원군 섭정 → 친정·개화 정책 → 대한제국 황제). 단계가 시작한 해에 점선과 이름표를 두고 그 단계의 칸을 적으며, 각 단계의 칸은 다음 단계나 시기 경계 전에 다 들어가도록 높이를 잡습니다.
- **대가야**는 왕별 재위 연도가 거의 전해지지 않아, 연도가 확인되는 왕만 놓고 나머지는 빗금 "미상" 칸으로 비워 둡니다. 화면 폭이 1000px 이상이면 금관가야와 한 줄을 반씩 나눠 오른쪽 반에 놓고(`half`), 그보다 좁으면 금관가야 줄 오른쪽에 나라 전체 기간만 가는 띠로 붙습니다. 그래서 넓은 화면의 5번째 줄은 1919년(임시 정부) 전까지 비어 있습니다.
- **덜 나온 왕은 흐리게** 표시합니다(기출 550문항 해설의 문제 설명에 한 번도 안 나오고 해설 전체에도 5문항 미만). 기준은 `dist/kings-weight.js`이고, 해설이 바뀌면 `node site/tools/count_kings.mjs`로 다시 만듭니다. 1910년 이후 띠는 세지 않고 흐리게 하지도 않습니다.
- 위쪽 시대 버튼(삼국·가야 ~ 현대)은 그 연도로 내려갑니다(`kings.html#y1945`처럼 주소로도 열 수 있습니다).
- 자료는 `dist/kings-data.js`(나라·왕·정부와 연도, `chart.lanes`·`chart.scales`·`chart.heads`, `periods`, `events`, `eras`, `notes`), 화면은 `dist/kings.js`, `dist/kings.css`입니다. 복위한 왕은 `r: 1`, 왕이 아닌 띠는 나라에 `kind`, 지금도 이어지는 띠·시기는 `now: true`를 붙입니다.

## 진도 저장

선택한 답, 확인 여부, 현재 문제를 같은 브라우저에 자동 저장합니다. 페이지를 닫거나
새로고침한 뒤 이어 풀 수 있습니다. 비공개 모드나 저장 제한 환경에서는 기록이
유지되지 않을 수 있으며 화면에 안내를 표시합니다.

파일 직접 열기와 로컬 HTTP 접속의 기록은 각각 따로 저장됩니다. 이전 모의고사
방식의 저장 기록은 삭제하지 않았으며, 새 학습 진도는 별도 저장 공간을 사용합니다.

## 로그인과 기록 동기화

로그인하면 푼 기록(답, 정답 확인 여부, 진행 위치)이 계정에 저장되어 다른 기기·브라우저에서도 이어 풀 수 있습니다. 서버는 Firebase(무료 Spark 요금제)를 쓰며, 설정 전에는 로그인 버튼이 나타나지 않고 기록은 이 브라우저에만 저장됩니다.

### 설정 (한 번만)
1. <https://console.firebase.google.com> → **프로젝트 추가** (Analytics는 꺼도 됩니다).
2. **프로젝트 설정 → 일반 → 내 앱 → 웹(`</>`)** 앱을 추가하고 나오는 `firebaseConfig` 값을 복사합니다.
3. **빌드 → Authentication → 시작하기 → Sign-in method**에서 **Google**과 **이메일/비밀번호**를 사용 설정합니다.
4. **빌드 → Firestore Database → 데이터베이스 만들기** (프로덕션 모드, 지역은 `asia-northeast3` 서울 권장). 만든 뒤 **규칙** 탭에 `firestore.rules` 내용을 붙여넣고 **게시**합니다.
5. **Authentication → 설정 → 승인된 도메인**에 `aicatveo3-prog.github.io` 를 추가합니다.
6. `dist/firebase-config.js` 의 `window.FIREBASE_CONFIG = null;` 을 2번에서 복사한 값으로 바꾸고 커밋·푸시합니다.

### 동작 방식
- 기록의 원본은 그대로 localStorage이고, 로그인 상태에서는 풀이를 저장할 때마다 `users/{uid}/progress/{회차}` 문서로 복사합니다.
- 로그인하면 클라우드와 이 기기의 기록을 회차마다 비교해 **더 최근에 푼 쪽**을 씁니다. 첫 로그인 때 이 기기에 있던 기록은 자동으로 올라갑니다.
- 아무것도 풀지 않은 새 시도는 클라우드 기록을 덮어쓰지 않습니다. ‘다시 풀기’는 답을 하나 고르는 시점부터 다른 기기에 반영됩니다.
- 로그아웃하면 이 브라우저의 학습 기록을 지웁니다(클라우드에는 남아 있고, 다음 로그인 때 다시 불러옵니다). 공용 PC에서 기록이 섞이지 않게 하기 위해서입니다.
- `firestore.rules` 덕분에 본인만 자기 기록을 읽고 쓸 수 있습니다.
- **기록 옮기기**(`dist/transfer.js`, 상단 `기록 옮기기` 버튼): 로컬 파일로 연 사이트와 GitHub 사이트처럼 주소가 다르면 브라우저 저장 공간이 따로라 기록이 보이지 않습니다. 한쪽에서 기록을 JSON 파일로 내보내고 다른 쪽에서 가져오면 합쳐집니다(진도는 회차·묶음마다, 풀이 기록·북마크는 문제마다 더 최근 것). 로그인 상태에서 가져오면 계정에도 올라갑니다. 파일로 연 화면(`file://`)에서는 Google 로그인이 되지 않으므로 이메일 로그인이나 이 기능을 씁니다.
- **문제별 풀이 기록**(`dist/solved.js`, `korean-history-study-v2-solved`, 계정에는 `progress/solved`): 회차·단원·유형·이론 창 어디서 풀었든 문제별로 모읍니다. 정답을 확인하면 기록되고, `다시 풀기`나 새로 시작을 해도 지워지지 않으며 결과만 마지막 풀이로 바뀝니다. 페이지를 열 때 기존 진도에서 빠진 문제를 채웁니다. 다른 기기와는 통째로 고르지 않고 문제별로 더 최근 것을 합칩니다.
- 동기화 로직 테스트: `node tools/sync-test.mjs`

## 압축 정리

상단 메뉴의 **압축 정리**(`dist/compact.html`)는 선사부터 현대까지 사건 452개를 시대마다 칸 구조(나라별 칸·왕대 연표·시기 연표·비교표)로 정리한 페이지입니다. 보기 전환은 없고, 칸 4개가 들어가지 않는 폭 760px 이하에서만 연도 순서대로 이은 사건 목록으로 보입니다. 한국사 연표가 왕·정부 단위라면, 압축 정리는 사건·제도 단위로 흐름을 외우는 용도입니다.

- **분야**(정치·경제·사회·문화·대외·운동)는 점 색으로 구분하고, 위쪽 칩이나 사건 아래 분야 이름을 누르면 그 분야만 남습니다.
- **주제 태그**(토지·화폐·교육 기관·무장 투쟁 등 48개)를 누르면 그 사건에 순번이 붙고, 맨 위에 `관료전 → 녹읍 폐지 → … → 관수관급제` 같은 **흐름 줄**이 생깁니다. 흐름 줄의 칸을 누르면 그 사건으로 이동합니다. 나머지 사건은 '숨기기' 또는 '흐리게'를 고릅니다.
- **핵심만 / 전체**: 기본은 핵심 사건 222개만 보입니다. 태그나 검색으로 거를 때는 흐름이 끊기지 않도록 해당 사건을 모두 보여 줍니다.
- 큰 사건(무신 정변, 동학 농민 운동 등)은 **세부 흐름**을 펼쳐 봅니다. 기간 사건은 점 대신 세로 막대, 같은 해가 이어지면 연도를 흐리게 씁니다.
- **연도 가리기 / 사건 가리기**: 가린 칸을 누르면 그 칸만 드러나고, '다시 가리기'로 되돌립니다.
- **순서 맞추기**: 지금 보이는 사건 중 연도가 서로 다른 5개를 섞어 내고, 먼저 일어난 순서대로 누르게 합니다(태그를 고른 뒤 누르면 그 주제 안에서 출제).
- 사건마다 **이론 정리 →** 링크가 있어 관련 주제(`theory.html#t12`)를 펼쳐 엽니다.
- 거른 상태는 주소에 남습니다(`compact.html#tag=토지`, `#field=eco`, `#q=서희`). 보기 설정(핵심/전체, 가리기, 숨기기/흐리게, 태그 목록 펼침)은 브라우저에 저장됩니다(`korean-history-compact-v1`, 학습 기록과 별개라 동기화하지 않음).
- 인쇄하면 조건·버튼이 빠지고 가리기가 풀리며 세부 흐름이 모두 펼쳐집니다.

**한 장으로 잇기**: 시대마다 상자를 따로 두지 않고 흰 판 한 장 안에 선사부터 현대까지 이어 그립니다. 시대가 바뀌는 곳은 타임라인 축 위의 큰 고리 마디(왼쪽에 기간, 오른쪽에 시대 이름·사건 수)로 표시하고, 이 시대 머리는 그 시대를 보는 동안 화면 위에 붙어 있습니다(좁은 화면에서는 시대 이동 줄 아래). 나라별 칸으로 보는 시대는 축이 그 시대 마디에서 멈췄다가 다음 시대 마디에서 다시 시작합니다.

**나라별 칸**: 삼국·가야와 통일신라·발해·후삼국은 나라마다 옅은 색 세로 띠를 깔고 세기 단위로 줄을 맞추며, 한 세기 안에서는 칸마다 사건을 위에서부터 쌓습니다. 연도는 가는 큰 숫자, 그 아래 제목입니다(칸이 나라를 말해 주므로 "고구려," 같은 앞말은 뺌). 여러 나라에 걸친 사건은 관련 칸마다 넣고 "↔ 신라"처럼 상대 나라를 붙입니다. 사건을 누르면 요점·세부 흐름·태그·이론 정리 링크가 펼쳐집니다. 남북국은 900년부터 칸이 신라·후백제·후고구려→고려·발해 넷으로 바뀝니다. 필터·흐름 줄·가리기(가린 칸은 첫 번째 누름에 드러남)·순서 맞추기는 칸 구조와 좁은 화면의 사건 목록에서 똑같이 작동합니다. 사건 목록에서는 사건 제목 앞에 나라 이름표가 붙습니다.

**통일신라·발해·후삼국의 왕별 묶음**: 삼국과 같은 모양으로 신라·발해·후백제·후고구려 칸 안을 왕별로 묶습니다. 후고구려 칸은 궁예 뒤에 고려 태조(왕건)를 이어 붙입니다. 카드는 신라 신문왕("왕권 강화"), 발해 선왕("해동성국 · 전성기"), 견훤·궁예("건국"), 고려 태조("후삼국 통일") 5개입니다. 연표 자료에 업적이 없는 견훤·궁예는 원고의 건국 사건 요점을, 고려 태조는 통일 무렵 정책(북진·결혼 정책·발해 유민 포용)만 카드 항목으로 씁니다(나머지는 고려 시대에). 780 혜공왕 피살 → 신라 하대는 하대의 시작이라 선덕왕 묶음에 들어가고, "9세기 선종과 풍수지리설 확산"은 특정 왕의 일이 아니라 칸 맨 위 왕 묶음 밖에 "시기 전체의 흐름"으로 둡니다. 업적 키워드 중 연도가 이 시대 밖인 것(예: 문무왕의 668 고구려 멸망)은 빼서 삼국 칸과 겹치지 않게 합니다.

**삼국의 모든 왕(재위 길이 카드)**: 삼국·가야는 고구려 28명·백제 31명·신라 30명(문무왕까지)·금관가야 10명, 모든 왕을 빠짐없이 보입니다. 왕은 즉위한 세기 줄에 한 번 나오고 그 왕의 사건은 세기와 관계없이 모두 그 카드에 들어갑니다(예: 영양왕 590 즉위 → 6세기 줄에 612 살수 대첩까지). 카드 높이는 재위 연수 × 2.4px(`px`)이고, 사건·업적이 그보다 길면 내용만큼 늘어나 내용이 잘리지 않습니다(최소 높이). 사건·업적이 있는 왕은 "346~375 · 29년"처럼 재위 기간과 연수를, 이 정리에 사건·업적이 없는 왕은 카드 대신 얇은 색 띠에 "진사왕 7년"처럼 연수만 씁니다(띠 길이도 재위 비례, 마우스를 올리면 재위 기간). 대가야는 왕 재위 자료가 거의 미상이라 대가야 사건(479 남제 사신, 562 멸망)은 왕 묶음 밖에 "대가야 · 왕 재위 자료 미상"으로 두고, 금관가야 왕 사이에 연도 순서로 끼웁니다. 거르지 않을 때는(핵심만 보기 포함) 모든 왕이 남아 왕 순서가 끊기지 않고, 거를 때는 해당 사건이 있는 왕만 남습니다. 원고에서는 `laneKings`의 `all: 1`, `px`, `looseNote`로 켭니다.

**삼국의 왕별 묶음**: 삼국·가야의 나라별 칸에서 고구려·백제·신라 칸 안을 왕별로 묶습니다. 왕 이름·재위 아래 그 세기의 사건과 한국사 연표의 업적 키워드(그 줄 사건 이름과 겹치는 것은 뺌)를 붙이고, 전성기 왕 4명(백제 근초고왕, 고구려 광개토대왕·장수왕, 신라 진흥왕)은 "전성기" 표시가 붙은 큰 카드에 업적을 목록으로 씁니다. 세기 경계에 걸친 왕은 사건이 있는 세기 줄에만 나오고(사건이 없으면 업적이 있을 때 즉위한 세기), 키워드는 처음 나오는 줄에만 붙습니다. 가야는 왕 자료(특히 대가야)가 불완전해 지금처럼 사건만 쌓습니다. 사건의 왕은 그 해에 즉위한 왕이 기본이고, 기록과 다른 475 한성 함락(개로왕)·554 관산성 전투(성왕)는 원고에서 직접 지정합니다. 거를 때는 보이는 사건이 없는 왕 묶음을 접고, 핵심만 보기에서는 업적이 있는 왕은 남깁니다.

원고는 `content/compact/<시대 id>.json`(시대 id는 `theory-map.json`과 같음)과 태그·분야·나라 목록 `content/compact/tags.json`입니다. 나라별 칸은 시대 파일의 `lanes`(구간별 칸 구성)와 사건의 `c`(나라 id, 여러 나라면 배열)로 정합니다. 칸 안 왕별 묶음은 `laneKings`(`countries`: 나라 id → 연표 자료 나라 id 또는 여러 나라를 이어 붙인 배열(`{ kingdom, kings: [첫 대수, 끝 대수], names }`), `boundary`: 왕이 바뀐 해 규칙, `cards`: 카드로 보일 왕 `{ c, n, kingdom?, badge, note, items?, color? }`(`key: 1`이면 굵게) 또는 `{ none }`(예: "기록 없음")입니다. 사건은 `cr`(줄 id면 줄 머리, 구간 id면 띠 아래)과 `cc`(칸 id, 그 줄의 칸 안)로 둡니다. 빌드는 없는 줄·칸, 줄 머리 사건 중복, 모르는 항목을 검사합니다. 칸에 `branches`(이름, 색, 태그 또는 이론 주제)를 두면 갈래 표시가 붙습니다. 키워드는 그 왕의 `acts` 중 시기 안의 것(첫 낱말이 그 시기 사건 이름·흐름 줄 이름에 있으면 뺌)과 `keys`를 합칩니다. 빌드는 시기가 바뀌는 해의 사건도 확인 목록에 보여 줍니다. 왕 목록·재위 연도·업적 키워드(고려는 `keys`, 조선은 `acts`)는 빌드할 때 `dist/kings-data.js`(한국사 연표 자료)에서 가져오므로, 왕 정보를 고치면 `build_compact.mjs`를 다시 실행합니다. 빌드는 `col` 누락·없는 칸·그 해에 재위한 왕이 없는 사건을 검사합니다. 고친 뒤 `node tools/build_compact.mjs`를 실행하면 `dist/compact-data.js`가 만들어집니다. 빌드는 모르는 항목·없는 태그·없는 이론 주제 이름·시대 안의 연도 순서 어긋남을 검사하고 멈춥니다. 사건 항목은 `tools/build_compact.mjs` 맨 위 설명을 보세요(`y` 연도, `t` 이름, `f` 분야, `n` 요점, `tags`, `core`, `k` 흐름 줄 이름, `th` 이론 주제, `sub` 세부 흐름 등).

폭이 600px 이하인 화면에서는 메뉴가 4개라 상단 메뉴를 로고·로그인 아래 별도 줄(옆으로 밀어 보기)로 둡니다(`theory.css`, 모든 페이지 공통).
